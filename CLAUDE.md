# CommerceBuilds/metricflow: rules for agents

This repository is CommerceBuilds' fork of dbt-labs' MetricFlow. Its default branch, `analyticsbuilds-main`, is a
dbt-labs release plus the fork's engine changes. analyticsbuilds-com pins one merged commit of it. Upstream's own
rules are in `AGENTS.md` and still apply; this file adds the fork's.

## Changes

- Mark every change `FORK:` in a comment or docstring at the change, saying what it does and why.
- Line 1 of every file the fork modifies is
  `# Modified by CommerceBuilds in the fork CommerceBuilds/metricflow; each change is marked `FORK:`.` A new file
  the fork adds says it is the fork's in its module docstring instead.
- `LICENSE` and `ATTRIBUTION.md` stay intact. Never edit, move or delete them.

## Which engine changes are allowed

The list of sanctioned engine changes is analyticsbuilds-com's `.claude/rules/metrics-layer.md`. A change that isn't
on that list needs the owner's yes on that file's wording first. That wording is agreed and changed in
analyticsbuilds-com, never here. A PR here that adds or changes an engine change quotes the exact wording it needs.

## Pull requests

- Every PR targets `analyticsbuilds-main`.
- The owner merges. An agent never merges a PR and never enables auto-merge.

## Tests

- A change ships with a test that fails if the change is reverted. Say in the PR how you checked that.
- The span tests (`tests_metricflow/fork_spans/`) also run with every dataflow optimization on
  (`DataflowPlanOptimization.all_optimizations()`), as the render service runs them.
- The fork's own tests run locally without a database: `PYTHONPATH=. pytest --noconftest tests_metricflow/fork_spans`.
  Upstream's suites, and any fork test that executes queries, run in the fork's CI (`Required Tests`).

## Snapshots

Upstream's snapshot files are regenerated by the fork's CI, never by hand: run `Required Tests` by hand
(`workflow_dispatch`) against the branch with **overwrite_snapshots** ticked. The job commits the changed snapshots to
the branch. A push made by that job starts no new run, so re-run the PR's checks afterwards. Explain every snapshot
change in the PR description.

## Writing

American English in everything written: code, comments, docstrings, commit messages and PR descriptions.
